# Agent Instructions

Guidance for AI coding assistants working **in this repository** (authoring and maintaining the plugin). For how the plugin is used by end users, see `README.md`.

## Project Overview

`bugsee-for-ai` is the Bugsee plugin for AI coding assistants (Claude Code, Cursor, OpenAI Codex). It provides:

- **Skills** — opinionated wizards that install and configure Bugsee SDKs, debug Bugsee issues, and upload symbols.
- **MCP server** — the Bugsee MCP at `https://api.bugsee.com/mcp`, declared inline in the Claude plugin manifest and in the repo-root `.mcp.json` (auto-discovered by Cursor), so issue context is available to the assistant.

## Plugin Structure

```
skills/                 # SDK setup, workflow, and internal skills (one SKILL.md per dir)
scripts/                # build-skill-tree.sh — regenerate + validate SKILL_TREE.md
assets/                 # logo.svg
.claude-plugin/         # Claude Code plugin metadata (+ inline MCP server)
.cursor-plugin/         # Cursor plugin metadata
.codex-plugin/          # OpenAI Codex plugin manifest
.agents/                # agent definitions used by the skill-drift workflow
.github/workflows/      # CI validation + weekly skill-drift detection (needs one-time setup)
warden.toml             # declared tool policy mirrored by the drift workflow's --allowedTools
.claude/settings.json   # plugin enablement + read-only permission allowlist
.mcp.json               # MCP server config for auto-discovery
AGENTS.md / CLAUDE.md   # this file (CLAUDE.md is a symlink to AGENTS.md)
SKILL_TREE.md           # generated sitemap of every skill
```

Every skill uses YAML frontmatter with `allowed-tools` — required by Cursor and harmless in Claude Code. Keep it in all skill files.

## MCP Server

The Bugsee MCP server (base URL `https://api.bugsee.com/mcp`; OAuth 2.1/PKCE, or token URL `https://api.bugsee.com/mcp/<token>`) exposes eleven tools across three families, plus the `/bugsee_fix` prompt:

- **Applications:** `list_applications`
- **Issues:** `list_issues`, `get_issue`, `get_issue_resource`
- **Builds:** `list_builds`, `list_latest_builds`, `get_build`, `get_build_by_commit`, `get_build_regressions`, `list_build_vulnerabilities`, `trigger_build_vuln_scan`

All are read-only except `trigger_build_vuln_scan` (queues a dependency-vulnerability scan; requires `modify` permission). Issue tools power `bugsee-fix-issues`; build tools power `bugsee-build-insights`. Tool reference: <https://docs.bugsee.com/mcp/usage/>. Configuration: <https://docs.bugsee.com/mcp/configuration/>.

## Skill Tree Navigation

- The two router skills (`bugsee-sdk-setup`, `bugsee-workflow`) carry `role: router` and stay visible in agent metadata.
- All other skills set `disable-model-invocation: true` and are loaded on demand when a router points to them. (Internal skills have no router.)
- `SKILL_TREE.md` is the flat sitemap of every skill, generated by the build script.

### Adding a new skill

1. Create `skills/<skill-name>/SKILL.md` with standard frontmatter (`name`, `description`, `license`, `category`, `parent`, `disable-model-invocation: true`, `allowed-tools`).
2. Add the breadcrumb as the first body line: `> [All Skills](../../SKILL_TREE.md) > [<Category>](../<router>/SKILL.md) > <Label>`.
3. Register the skill in its parent router's table (and in this file).
4. Run `scripts/build-skill-tree.sh` to regenerate `SKILL_TREE.md` and validate.
5. CI validates automatically on every PR.

The `bugsee-skill-creator` skill documents this end-to-end.

## Key Conventions

- **Bugsee-only.** No file in this repo may reference or mention other monitoring vendors, their hosted skill sites, or their MCP endpoints. Use `docs.bugsee.com` and `api.bugsee.com`. The Validate Skill Tree CI job hard-fails on the primary competitor's name; reviewers enforce the broader no-other-vendor rule.
- Verify SDK APIs against the docs (`docs.bugsee.com`) and the SDK source (`github.com/bugsee`) — never invent API names.
- Keep skills single-file unless a platform genuinely needs reference files.
- When you change the drift workflow's `--allowedTools`, update `warden.toml`'s allow list to match — it mirrors that allowlist but is not auto-enforced.
- Codex compatibility: Codex auto-discovers `./skills` and `./.mcp.json` and ignores the `disable-model-invocation` flag (so the shared skills work in Codex unchanged). Codex's optional `validate_plugin.py` lint flags that flag — expected, not a load-time error.
